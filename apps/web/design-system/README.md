# NomadCore — дизайн-система, этап 1

Что здесь лежит: **токены и примитивы**, а не макеты.

```
tokens.css            все переменные: цвет, шкала, отступы, тач, движение
tailwind-preset.ts    Tailwind читает те же переменные
primitives/*.vue      NcButton, NcPill, NcRow, NcField, NcStepper,
                      NcSegmented, NcBanner, NcSheet, NcIcon
```

Спецификация с измеренным контрастом, шкалой и стресс-тестами —
`NomadCore Design System.dc.html` в корне проекта.

## Три правила, из которых выведено остальное

**1. Иерархия действий строится контрастом, а вес назначается по цене ошибки.**

Контраст говорит, какое действие ГЛАВНОЕ, — он не означает «важное». Заливка
на экране ровно одна, у единственного главного действия; всё остальное —
контур. Уровни:

| Вес | Когда | Пример |
|---|---|---|
| заливка | то, чего экран ждёт ПРЯМО СЕЙЧАС и что дёшево откатить | «Подтвердить · Петров Игорь» |
| контур | рутинное действие в строке | «Заселить», «Отклонить» |
| приглушённый контур + подтверждение | статус разойдётся с физическим миром | «Выселить» |
| красный контур | необратимое | «Отменить бронь» |
| только текст, значок в шапке | утилита и навигация, последствий ноль | «+», «КЫР» |

Чем выше цена ошибки, тем менее нажимаемым выглядит действие.

Три следствия, которые легко нарушить:

- **Заливку получает не самое частое действие, а самое срочное.** «+ Новая
  бронь» безопаснее всех и потому не залита вовсе: создание брони — это
  «всегда», а экран «Сегодня» отвечает на «что делать сейчас». Значок «+»
  44×44 живёт в шапке.
- **Выселение не залито никогда**, в том числе на своей карточке. Оно
  помечает гостя выехавшим, пока он в номере.
- **Когда экран ничего не требует, залитых кнопок ноль.** Это нормальное
  состояние, а не пустота: на «Занятости» и на карточке гостя в доме
  заливки нет.

Переключатели режима (сегменты, вкладки) — состояние, а не действие: заливку
они не берут, выбранный помечается фоном band, жирным начертанием и
подчёркиванием.

Два уточнения к счёту «ровно одна»:

- **Модальная шторка считается отдельно.** Пока она открыта, фон под ней
  неактивен, и у шторки своя единственная заливка. Две заливки на снимке —
  норма, если одна из них принадлежит открытому слою.
- **Глобальное действие не повторяется в строках.** «Включить сеть» относится
  ко всей очереди, а не к отдельной мутации: одна копия внизу экрана.
  Дублирование в каждой карточке давало N+1 залитых кнопок — и, что хуже,
  громче всех оказывалось самое безопасное действие.

Проверка: обесцветьте экран и посчитайте залитые кнопки. Ровно одна —
иерархия есть; больше одной — главного действия нет; ноль — экран ничего не
требует, и это тоже ответ. Доказательства для экранов владельца:
`proof/grayscale-today.png`, `proof/grayscale-grid.png`.

**2. Цвет означает ровно одну вещь.**
Янтарный — только «требует внимания»: статус HOLD и предупреждение о
документах. Он не заливает кнопки. Раньше «Подтвердить» был янтарным, и один
тон работал и действием, и предупреждением — это ошибка, исправлена.

**3. Ниже 13px в поле не опускаемся.**
У шкалы `field` семь ступеней от 13 до 34px. Для кабинета госагентства есть
отдельная шкала `desk` от 12px — там ноутбук, а не солнце.

## Цвета, измеренные к фону своей темы

| Токен | Светлая | Тёмная |
|---|---|---|
| `--nc-text-primary` | 18,7:1 | 16,0:1 |
| `--nc-text-secondary` | 8,7:1 | 8,8:1 |
| `--nc-text-tertiary` | 5,2:1 | 5,4:1 |
| статусы с текстом на заливке | 6,6–6,7:1 | 6,8–7,4:1 |

`#8A8C86` (3,4:1) и `#9A9C96` (2,8:1) из системы **исключены как текстовые** —
они годятся только на границы и неактивные точки шкалы состояния.

## Тёмная тема — отдельный набор, не инверсия

Сценарий другой: ночная стойка. Фон не чистый чёрный (дешёвый LCD показывает
серые пятна), текст не чистый белый (21:1 слепит в темноте, 16:1 достаточно).
Статусные тона подняты по светлоте с 0,47 до 0,72–0,76 и приглушены по
цветности, текст на заливке становится тёмным.

## Имена отступов равны значениям

`--nc-space-12` — это 12px. Индексных имён в системе нет: `space-4`, который
означает 12px, разработчик всё равно однажды прочитает как «4 пикселя».
Tailwind-шкала отступов переопределена целиком по той же причине — иначе
`p-4` (16px у Tailwind) и `space-4` (4px у нас) существуют одновременно.

## Контраст проверяется на худшем фоне, а не на surface

Правило: **тёмный текст проверяется на самом тёмном фоне своей темы, светлый —
на самом светлом.** Запас определяет худший случай, а не `--nc-bg-surface`.

`--nc-text-tertiary` раньше был `#6B6D68`: 5,98:1 на белом — проходит, но на
`--nc-bg-canvas` `#EDEDEA` уже 4,46:1. Теперь `#626460`: 5,98 на surface,
5,10 на canvas, **4,56 на `--nc-bg-band` `#E1E1DC`** — это и есть худший фон
светлой темы. В тёмной теме худший фон, наоборот, самый светлый:
`--nc-text-tertiary` `#8B8F89` на `--nc-bg-band` `#242729` даёт 4,57:1.

## Подключение

```ts
// nuxt.config.ts
css: ['~/design-system/tokens.css']
// tailwind.config.ts
import { ncPreset } from './design-system/tailwind-preset'
export default { presets: [ncPreset], content: [...] }
```

Инлайновых стилей в компонентах нет. Литералов цвета и кегля в компонентах нет.
Если примитиву не хватает токена — заводится токен, а не литерал.
